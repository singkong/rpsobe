# 08 — User Persona

## Persona 1: Dosen Muda — "Rina"

### Profil

| Atribut | Detail |
|---------|--------|
| Nama | Rina Maulida, S.Kom., M.T. |
| Usia | 28 tahun |
| Jabatan | Dosen Tetap, Prodi Informatika |
| Pengalaman Mengajar | 2 tahun |
| Pengalaman OBE | Pemula — baru mengenal OBE |
| Institusi | Universitas Swasta di Bandung |
| Tech Savvy | Tinggi (Gen Z, familiar dengan teknologi) |

### Tujuan

- Menyusun RPS dengan benar sesuai standar OBE
- Memahami constructive alignment
- Mendapatkan validasi sebelum RPS direview kaprodi
- Menghemat waktu penyusunan RPS

### Pain Points

- Tidak pernah mendapat pelatihan OBE formal
- Bingung membedakan CPL, CPMK, Sub-CPMK
- Tidak tahu apakah RPS sudah selaras atau belum
- Review manual oleh kaprodi lambat (5-7 hari)

### Kebutuhan Fitur

- Wizard yang memandu langkah demi langkah
- AI Assistant untuk membantu generate CPMK dan komponen lain
- AI Validator untuk memastikan RPS benar
- Progress tracking RPS

### Quote

> "Saya ingin menyusun RPS yang benar, tapi saya tidak punya waktu untuk belajar teori OBE dari nol. Bantu saya dengan tool yang pintar."

## Persona 2: Dosen Senior — "Prof. Budi"

### Profil

| Atribut | Detail |
|---------|--------|
| Nama | Prof. Dr. Budi Santoso, M.Sc. |
| Usia | 55 tahun |
| Jabatan | Guru Besar, Prodi Teknik Sipil |
| Pengalaman Mengajar | 25 tahun |
| Pengalaman OBE | Menengah — pernah mengikuti workshop |
| Institusi | Universitas Negeri di Yogyakarta |
| Tech Savvy | Rendah — kurang nyaman dengan teknologi baru |

### Tujuan

- Menyusun RPS yang memenuhi standar akreditasi internasional (ABET)
- Menggunakan template yang sudah familiar
- Memastikan referensi terbaru
- Kolaborasi dengan tim dosen

### Pain Points

- Terbiasa dengan Word — enggan belajar sistem baru
- Template RPS sering berubah
- Banyak mata kuliah yang harus disusun RPS-nya
- Ingin RPS langsung jadi tanpa banyak klik

### Kebutuhan Fitur

- UI sederhana dan familiar (minimalist)
- Template yang bisa langsung diisi
- AI untuk generate konten (referensi, materi)
- Export ke Word dengan format yang rapi

### Quote

> "Saya sudah 25 tahun mengajar. Saya tahu materi saya. Bantu saya menuangkannya ke format RPS yang sesuai standar baru ini, tanpa ribet."

## Persona 3: Kaprodi — "Dr. Ahmad"

### Profil

| Atribut | Detail |
|---------|--------|
| Nama | Dr. Ahmad Fauzi, S.T., M.Eng. |
| Usia | 42 tahun |
| Jabatan | Ketua Program Studi Teknik Elektro |
| Pengalaman Manajemen | 5 tahun sebagai kaprodi |
| Pengalaman OBE | Tinggi — aktif di tim akreditasi |
| Institusi | Institut Teknologi di Surabaya |
| Tech Savvy | Menengah |

### Tujuan

- Memastikan seluruh RPS di prodi berkualitas
- Memonitor progress penyusunan RPS
- Mempercepat proses review dan approval
- Menyiapkan dokumen akreditasi

### Pain Points

- 50+ dosen dengan RPS yang harus direview setiap semester
- Tidak bisa memonitor status RPS satu per satu
- Review manual memakan waktu 2 minggu penuh
- Format RPS tidak seragam antar dosen

### Kebutuhan Fitur

- Dashboard prodi (status RPS semua dosen)
- Workflow review yang terstruktur
- AI Reviewer untuk membantu review
- Reporting dan export untuk akreditasi

### Quote

> "Saya butuh dashboard yang memberi tahu saya sekilas: siapa yang sudah selesai, siapa yang perlu direview, dan mana yang bermasalah. Jangan sampai saya harus ngecek satu per satu."

## Persona 4: Reviewer — "Eka"

### Profil

| Atribut | Detail |
|---------|--------|
| Nama | Eka Pratiwi, S.Pd., M.Pd. |
| Usia | 35 tahun |
| Jabatan | Dosen Prodi Pendidikan + Reviewer RPS |
| Pengalaman Review | 3 tahun |
| Pengalaman OBE | Tinggi — tersertifikasi reviewer |
| Institusi | Universitas Swasta di Jakarta |
| Tech Savvy | Menengah |

### Tujuan

- Mereview RPS secara efisien (10+ RPS per minggu)
- Memberikan feedback yang konstruktif dan terukur
- Memastikan kualitas RPS sesuai standar

### Pain Points

- Checklist review panjang (40+ item) — sulit konsisten
- Tidak ada panduan standar skoring
- Komunikasi dengan dosen via email lambat
- Sulit melacak apakah dosen sudah merevisi

### Kebutuhan Fitur

- Checklist review terstruktur
- AI-assisted review untuk item otomatis
- Skoring terstandarisasi
- Komentar inline per komponen
- Tracking revisi dosen

### Quote

> "Saya review 10 RPS per minggu. Beri saya tool yang bisa otomatis cek alignment, sehingga saya fokus pada substansi. Dan jangan suruh saya kirim email bolak-balik."

## Persona 5: LPM — "Dr. Sari"

### Profil

| Atribut | Detail |
|---------|--------|
| Nama | Dr. Sari Wulandari, M.M. |
| Usia | 48 tahun |
| Jabatan | Kepala LPM (Lembaga Penjaminan Mutu) |
| Pengalaman QA | 10 tahun |
| Pengalaman OBE | Sangat Tinggi — auditor BAN-PT |
| Institusi | Universitas Besar di Medan |
| Tech Savvy | Menengah |

### Tujuan

- Memastikan seluruh RPS memenuhi standar mutu
- Menyediakan bukti audit untuk akreditasi
- Menganalisis tren kualitas RPS
- Membuat laporan ke rektorat

### Pain Points

- RPS tersebar di banyak tempat (Word, Google Drive, email)
- Tidak ada metrik kualitas RPS yang terukur
- Sulit membuktikan continuous improvement ke auditor
- Audit manual memakan waktu berbulan-bulan

### Kebutuhan Fitur

- Dashboard mutu (seluruh universitas)
- AI Validator massal (validasi semua RPS sekaligus)
- Audit trail lengkap
- Reporting dan statistik kualitas
- Export untuk auditor

### Quote

> "Saya ingin satu klik dan tahu berapa persen RPS yang constructive alignment-nya baik, mana yang perlu perbaikan, dan buktikan itu semua ke BAN-PT."
